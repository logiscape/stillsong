# AGENTS.md

This file provides guidance to Claude Code (claude.ai/code), Codex, and other AI agents when working with code in this repository.

Stillsong 2 is a Windows desktop app (Tauri v2 + React 18 + TypeScript, GPL-3.0) that turns a photo into a song. Everything runs locally: Gemma 4 12B (via `llama-server`) looks at the photo and writes caption + lyrics; YuE2 (via headless ComfyUI: core nodes plus Stillsong 2's own first-party node package, nothing third-party) writes a melody plan and performs the song. Both are child processes the app downloads on first run, supervises, and binds to 127.0.0.1. The README covers the product and the user-facing setup; this file covers what the code depends on.

**Stillsong 1 and Stillsong 2.** The original app (MiniMax Music 3, composition codes, the ComfyUI-Stillsong overlay) is maintained on the `v1` branch; this branch is Stillsong 2. The two are separate products that install and run side by side on one PC (see *Side-by-side identity*). Stillsong 2's songwriting (Gemma prompts, few-shots, linter, repair loop, instrumental skeleton) is deliberately byte-identical to Stillsong 1's for now; change it only as a deliberate experiment.

## Project principles

1. **The image analysis and song generation runs locally on the User's PC.** The app never automatically uploads or shares any content the user provides, or the songs that Stillsong generates. The user must choose to export and share them, if they wish to do so.

2. **The app never auto updates after the one-time initial setup.** The models and components installed by the app do not automatically update, unless the user initiates an update or configuration change.

3. **The app and the components installed by the app never upload usage statistics, crash reports, etc.** (Anything done by the user's operating system or external services not setup by the app are considered out of the project's control and out of scope of these principles)

4. **All commits are human-initiated.** Agents must never run `git commit`, `git push`, or tag releases. Leave verified work in the working tree for the human user to review, approve, and commit.

These core principles should be built into the architecture of the app, rather than a promise that the Stillsong developer is "doing the right thing". In other words, another company can't acquire Stillsong and remotely flip on an "auto update" switch without releasing a new version that the user must install on their own.

The app should follow standard best practices (eg. check the hashes for known pinned components) for securely obtaining the components from official sources and CDNs.

```

npx vitest run src/engine/__tests__/linter.test.ts   # one test file

npm run typecheck              # both tsconfigs (app + tests)
npm run tauri dev              # run the app (Vite on :1433); fully self-hosted, no env needed
npm run tauri build            # unsigned NSIS installer -> src-tauri/target/release/bundle/nsis/
npm run test:live              # E2E against a real ComfyUI on :8000 (renders drafts, 2–6 min)
npm run check:manifest         # probe every pinned URL/hop/size in components.json (CI)
node scripts/tree-digest.mjs <tar.gz|dir>  # treeSha256 of a source archive (ComfyUI bump)
node --test scripts/tree-digest.test.mjs physical-release/lib/layout.test.mjs  # Node mirrors of Rust manifest logic (CI)
node scripts/nodes-smoke.mjs   # live check of comfy-nodes/ComfyUI-Stillsong2 against ComfyUI on :8000 (renders, ~3 min)
node scripts/example-takes.mjs # remake examples/*.take.safetensors (only writes a take whose audio matches the shipped MP3)
npm run lock:python            # regenerate python.wheels lock (release-time, after ComfyUI bump)
npm run licenses               # regenerate THIRD-PARTY-LICENSES.txt after dep changes
```

Rust (run in `src-tauri/`): `cargo test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`. CI (`ci.yml`) enforces all three plus typecheck/test/check-manifest on pushes to `main` and `v2` and on pull requests — other branch pushes run nothing, so run them locally. `cargo test first_run_headless` (with `STILLSONG2_E2E_COMPONENTS=<dir>`, optionally `STILLSONG2_E2E_SKIP_MODELS=1`) is the headless production first run that `first-run.yml` executes on manifest/bootstrap changes; it also asserts the pinned ComfyUI ships `comfy_extras/nodes_yue2.py`.

Dev env vars (all `STILLSONG2_*`, never Stillsong 1's `STILLSONG_*`): `STILLSONG2_COMFY_URL` / `STILLSONG2_LLM_URL` make the supervisor treat that service as external instead of spawning it; `STILLSONG2_COMPONENTS` overrides the components dir (default `%LOCALAPPDATA%\com.logiscape.stillsong2\components\`). `scripts\dev-comfy.ps1` launches the components copy of ComfyUI standalone on :8000 with the supervisor's exact interpreter/flags (for live tests); under PowerShell 5.1 its native-stderr handling can abort the launch when redirected — run `python-env\Scripts\python.exe -s ComfyUI\main.py --port 8000 --base-directory <components>\comfy-data --offline --disable-all-custom-nodes --whitelist-custom-nodes ComfyUI-Stillsong2` from the components dir instead, after copying `comfy-nodes\ComfyUI-Stillsong2` into `comfy-data\custom_nodes` (the script does both; without the package the live suite's edit test fails on purpose rather than test the fallback). **One renderer on the GPU at a time** — never run the app alongside a standalone ComfyUI that is rendering. `tauri dev` watches `src-tauri/`, so editing Rust restarts the app mid-render.

Live tests are gated on `STILLSONG2_LIVE=1`, which only `npm run test:live` sets (via cross-env): running `live.test.ts` or `live-cowriter.test.ts` through plain `npx vitest run` skips every test and reports green without rendering anything. They target a ComfyUI on `:8000` unless `STILLSONG2_COMFY_URL` says otherwise, and spawn their own llama-server on 17901 from `STILLSONG2_COMPONENTS` (`livePorts.ts`). Files run sequentially (`--no-file-parallelism`) on purpose: parallel files would put Gemma and ComfyUI on the GPU at once. `STILLSONG2_PHOTO=<path>` overrides the sample photo.

## Architecture

Three layers with a hard boundary:

- **`src/engine/`** — pure TypeScript core. No UI, no Tauri imports. Every side effect goes through the interfaces in `ports.ts` (`Db`, `HttpTransport`, `WsTransport`, `FileStore`, `Clock`, `Runtime`). Tests in `__tests__/` inject fakes from `fakes.ts`; `livePorts.ts` provides Node-backed real ports for the live suite.
  - `domain/` — `SongSpec` and friends (`types.ts`: `MAX_DURATION_SEC`, `YUE2_CHECKPOINT`, `RENDER_DEFAULTS`), `validate.ts`, `duration.ts` (`renderCap` = the co-writer's length budget only; hardware tiers; driver floor).
  - `cowriter/` — `LlmClient` over llama-server's OpenAI-compatible API, `guides.ts` (prompts, per-source vision analysis), `Cowriter.compose` (analysis → compose → silent lint-repair round), `linter.ts`, `lyrics.ts` (`parseLyrics`). Unchanged from Stillsong 1, including the MiniMax wording in `WRITER_PERSONA` — on purpose (see above).
  - `domain/editWindows.ts` — pure: turns the alignment series (per-frame log-probability drop) into the frame windows a "keep the rest" edit sings again; `mergeWindows` widens them after a failed check.
  - `comfy/` — `ComfyClient` (HTTP + WS; `history()` also returns PreviewAny `texts`; `uploadTemp` sends a library file to ComfyUI's temp folder), `graphBuilder.ts` (`buildGraph` with `capture`, `buildAlignGraph`, `buildEditGraph`) + typed node constructors in `nodes.ts`, `NODE_PHASES` (node id → phase) and `EDIT_PHASES` (in `graphBuilder.ts`), `events.ts` (`ProgressTracker`).
  - `orchestrator/vram.ts` — `VramArbiter`: LLM and ComfyUI weights are never resident together. Probe-before-transition; stopping the LLM resolves only when the process has exited.
  - `repo/` — SQLite repos (songs, photos, jobs, settings). `migrations.ts` (in `src/engine/`, not `repo/`) is an ordered list of SQL strings plus guarded `ADDED_COLUMNS`.
  - `index.ts` — `Engine`: `createFromPhoto` one-shot pipeline (emits `creation_stage` for preparing → looking → writing → studio; the store derives composing → rendering → finishing from `progress` events), job queue/runner (`runRender` = one prompt; `runEdit` = the "keep the rest" pipeline, several prompts through `runPrompt`), `trackToCompletion` (WS + history-poll fallback), harvest (`composedLength`, `performedPlan`, the take), `recoverInFlight` on boot, boot-time sweeps (`sweepComfyOutputs`, `sweepOrphanPhotos`).
- **`src/adapters/tauriPorts.ts`** — the one Tauri implementation of `Ports`, over the Rust commands.
- **`src-tauri/src/`** — thin Rust shell, one module per concern: `identity.rs` (everything machine-level that must not collide with Stillsong 1: registry key, port range, the cross-app studio lock, v1 detection), `supervisor.rs` (spawns llama-server/ComfyUI under a Job Object so they die with the app; dynamic ports 17900–17999 with an owner check on both children; crash-restart-once for ComfyUI; takes the studio lock before spawning), `downloads.rs` (resumable, hash-verified, host-allowlisted component downloads), `components.rs` (extraction + offline uv venv bootstrap + verify), `manifest.rs` (`components.json` compiled in via `include_str!`; the web view only names artifacts by id), `nodes.rs` (the first-party ComfyUI node package, compiled in the same way and written into `comfy-data/custom_nodes` before every spawn; the launch flags that load it and nothing else), `gpu.rs` (nvidia-smi → DXGI fallback), `http.rs`/`ws.rs` (loopback-only bridge; `http_upload` posts one library file to loopback), `files.rs` (library-relative file ops).

UI: `src/state/store.ts` (useSyncExternalStore; subscribes to engine events; owns the single shared audio element) and `src/state/remix.ts` (`remixTake`: the seed and plan a remix performs — a new melody always takes a new seed, since the same seed and inputs write the same plan; `offersKeepRest` / `keepRestTake`: when a remix may keep the rest of the recording, and the spec that does) → `src/ui/screens/*` → design-system primitives in `src/ui/ds/` and tokens in `src/ui/tokens/`. `src/state/paintSession.ts` holds the in-progress "Draw Something" canvas in memory until `song_done`. The "Twilight Gallery" design language, voice/copy rules, and a prototyping UI kit live in `design-kit/` (its `readme.md` is the brand reference; note it was authored from a brief, not from this code).

**No third-party custom nodes, ever; one first-party package.** Stillsong 2 builds its graphs from ComfyUI core nodes (`CheckpointLoaderSimple`, `YuE2GenerateABC`, `YuE2GenerateMusic`, `EmptyYuE2LatentAudio`, `PreviewAny`, `ConditioningZeroOut`, `KSampler`, `VAEDecodeAudio`, `SaveAudioAdvanced`) and from its own package, `comfy-nodes/ComfyUI-Stillsong2` (`Stillsong2Perform`, `Stillsong2SaveTake`, `Stillsong2LoadTake`, `Stillsong2Align`, `Stillsong2HoldLatent`, `Stillsong2RestoreLatent`; its README has the provenance). The rule exists to keep untrusted third-party code out of the studio; a package this repository builds and verifies is not that. It is delivered by construction: the sources are compiled into the app (`nodes.rs`), rewritten into `comfy-data/custom_nodes/ComfyUI-Stillsong2` before every spawn, and ComfyUI is launched with `--disable-all-custom-nodes --whitelist-custom-nodes ComfyUI-Stillsong2` (last on the command line: the whitelist takes one or more names), so nothing else in that folder loads. If writing the package fails, the folder is not whitelisted at all (`nodes::launch_flags(false)`): it could still hold another build's files. The package pins the exact `comfy/text_encoders/yue2.py` it was derived from (`PINNED_YUE2_SHA256`) and refuses to load against another; the engine probes for `Stillsong2Perform` when a render starts and, without it, renders through the core nodes (no take is saved, and partial edits are not offered for those songs). An ordinary render runs upstream's own sampling either way: the package only hands out the tokens upstream drops. Only a partial re-performance uses the adapted copy of `_generate`.

**Takes and "Keep the rest".** Every render made with the package saves its take beside the MP3: `songs/<id>.take.safetensors` (`song.take_path`), holding the 25 Hz music tokens (as int16 codec codes) and the final float32 latent. A remix that only rewords existing lines (`offersKeepRest`: same sections, same line counts, same caption/plan/steps/guidance) can then set `spec.edit = { sourceId }`, and `Engine.runEdit` performs the source's take again: (1) upload the take to ComfyUI's temp folder; (2) alignment prompt: replay the take under the original and the edited sheet, `editWindows()` turns the drop series into frame windows; (3) edit prompt: tokens forced and latent held outside the windows, the windows sung anew, a new take saved; (4) the same alignment on the new take, read from ComfyUI's output folder: old words left in widen the windows once (`mergeWindows`) and step 3 runs again. It never turns into a whole remix on its own: it fails with a plain reason and the Create screen offers "Sing it all again" (`Engine.retryWhole`, which strips `spec.edit` from the same row). An edited song's spec is not a recipe for its recording (the kept parts come from the source's take), so `remixSpec` drops `edit`. Only the edit prompt's id is stored on the job; a cancel between prompts is remembered in `Engine.cancelling`, because ComfyUI forgets an interrupt when its next prompt starts. `recoverInFlight` never harvests an edit's recorded prompt (its check may not have run, and its windows lived in the engine that is gone): the edit is requeued and starts over. Every attempt that is not harvested has its files removed from ComfyUI's output, on the error paths too, since each attempt saves under a fresh prefix and the sweep keeps a living song's files.

`examples/` is the three-song starter library (CC BY 4.0 media + `examples.json`), bundled as a Tauri resource. `src/engine/examples.ts` (`seedExamples`, from `Engine.create`) imports it through the ordinary repos into an *empty* library exactly once, recording the outcome in the `examplesSeeded` setting: a library that already has songs is skipped for good, and deleted examples never come back. Song ids are fixed in the manifest so a failed seed resumes without duplicates. Never ship a pre-built database — every stored path is absolute. Each example carries its melody plan inline (`abc`), so "Keep melody" works on it, and ships its take (`take`, a `.take.safetensors` file), so "Keep the rest" works on it on any GPU. `.gitignore` ignores `*.safetensors` except `examples/*.take.safetensors`; `examplesFiles.test.ts` fails if a file the manifest names is not in the folder (the importer itself forgives a missing take). To change an example: re-render, copy the MP3 + the photo (EXIF-stripped, ≤ 2048 px) into `examples/`, write the ID3 disclosure comment into the MP3, run `node scripts/example-takes.mjs` (it writes a take only when the audio it performs is byte-identical to the MP3), update `examples.json` (bump `version`).

### Side-by-side identity

Stillsong 1 (`com.logiscape.stillsong`) and Stillsong 2 (`com.logiscape.stillsong2`) install and run independently on one PC. Never let this build name anything of v1's:

| | Stillsong 1 | Stillsong 2 |
|---|---|---|
| Product / identifier | Stillsong / `com.logiscape.stillsong` | Stillsong 2 / `com.logiscape.stillsong2` |
| App data, library, DB, WebView2 profile | `%APPDATA%` / `%LOCALAPPDATA%\com.logiscape.stillsong` | `…\com.logiscape.stillsong2` (all derived from the identifier) |
| Default components dir | `%LOCALAPPDATA%\com.logiscape.stillsong\components` | `<app local data>\components` (derived, `lib.rs`) |
| Registry (uninstaller's components pointer) | `HKCU\Software\Logiscape\Stillsong` | `HKCU\Software\Logiscape\Stillsong 2` (`identity::REGISTRY_KEY`, `installer-hooks.nsh`) |
| Child ports | 17800–17899 | 17900–17999 (`identity::PORT_RANGE`) |
| Dev vars / Vite | `STILLSONG_*` / :1432 | `STILLSONG2_*` / :1433 |
| ComfyUI output folder | `audio/stillsong` | `audio/stillsong2` (the output sweep never touches v1's) |

A product name shared with v1 would make the v2 installer treat v1 as an older copy and offer to uninstall it (silently: everything, library included). GPU sharing across apps: the supervisor holds a named kernel object, `Local\Logiscape.Stillsong.Studio` (`identity::StudioLock`, an open handle — not mutex ownership, so it moves between threads), while its children run, and refuses to start a studio while another holder exists or while Stillsong 1 (`Stillsong.exe`, which predates the lock) is running. Released in `stop_all`. A future v1 release should take the same lock.

### Supply chain

`components.json` pins every first-run download (uv, python-build-standalone, ComfyUI at a commit, llama.cpp, models, and `python.wheels` — one hashed wheel per package). `python.exclude` names packages ComfyUI's requirements resolve but the wheelhouse deliberately omits (today the six `comfyui-workflow-templates-media-*` gallery bundles, 513 MB): `lock-python.mjs` drops them *after* `uv pip compile` and fails on a name the resolution lacks, so a stale entry after a bump cannot silently do nothing. `npm run lock:python -- --freeze` re-locks with every current wheel pinned, for manifest-only changes that must not move other packages. Setup resolves nothing: `uv venv --offline` then `uv pip sync --offline --no-index --require-hashes` from the wheelhouse, with inherited `UV_*`/`PIP_*`/`LLAMA_ARG_*` (by prefix) and `PYTHONPATH`/`PYTHONHOME`/`PYTHONSTARTUP`/`PYTHONUSERBASE`/`VIRTUAL_ENV`/`CONDA_PREFIX` (by name) scrubbed — other `PYTHON*` variables pass through. `allowedHosts` is enforced on the first request only; redirect hops need only https (CDN hostnames churn); size + sha256 bind the bytes. The one exception is ComfyUI, the only GitHub-*generated* source archive (`/archive/<commit>.tar.gz`): GitHub guarantees the contents of a commit archive but not its compressed bytes (it regenerated every tarball in January 2023 and promises only six months' notice before doing so again), and a byte pin would break fresh installs of every shipped release at once, since the app never updates itself. So that item carries `treeSha256` instead of `sha256` — the sha256 of a `sha256sum`-style listing of every extracted regular file, sorted by path (`tree_sha256` in `components.rs`, mirrored bit-for-bit by `scripts/tree-digest.mjs`) — and its `size` is nominal: the downloader accepts up to `TREE_BOUND_SIZE_SLACK` (2×) and `extract_item` unpacks into `ComfyUI.unpacking`, digests, and swaps in only a matching tree. Because those bytes are unverified until then, that unpack refuses links and anything but files and directories (a symlink is invisible to the digest) and is capped at `TREE_BOUND_UNPACK_SLACK` (64×) bytes and `TREE_BOUND_MAX_ENTRIES` entries, with the decompressed stream itself bounded (`UnpackLimits::max_stream_bytes`) because tar-rs buffers pax/long-name metadata before yielding an entry; an archive it rejects is deleted so a retry downloads afresh (the downloader accepts an existing file as complete). `scripts/tree-digest.mjs` refuses the same things, so `check:manifest` and the disc build flag what setup would. `check:manifest` also refuses a `github.com/…/archive/` URL pinned by `sha256`.

The music model is one file: `music-checkpoint` = `Comfy-Org/YuE2` `checkpoints/yue2_3b_int8_convrot.safetensors` at revision `2f76ca75e6ee094169de899cc7fc99d6887e2196` (3,960,938,800 B), installed to `comfy-data/models/checkpoints/`. Runtime pins (uv, CPython, ComfyUI v0.42.4, wheels, llama.cpp, Gemma) started identical to Stillsong 1's `2026.11.05-1` manifest.

**Manifest version and the studio update.** `<components>/.install-complete` holds the `manifestVersion` the install was built from (Stillsong 2 versions are prefixed `v2-`). At boot the supervisor classifies the dir (`install_state_in`: not installed / needs update / updating / ready) and only a *ready* install is ever started: a studio from another manifest may not know this build's flags or ship the nodes the graph uses. Anything else routes to the update screen (`UpdateScreen`), which is user-initiated: it stops the children, deletes the runtime dirs (`uv`, `python-dist`, `ComfyUI`, `llama`, `python-env`, `uv-cache`), prunes `_downloads` to current-manifest files, size-checks the models, and re-runs the ordinary setup install (`SetupScreen mode="update"`) into the same folder; models, `comfy-data/`, and the library are kept. The app never checks for updates: a new manifest only ever arrives inside a new build the user installed. So **bump `manifestVersion` whenever any pin changes** and **pin launch flags to the manifest's ComfyUI — no per-version compatibility tables**.

Post-setup disk hygiene: `_downloads/` (archives + wheelhouse) is deleted once the install is complete *and current* (`Supervisor::remove_downloads`, at setup finish and every boot). **Leave `uv-cache/` alone** outside the update path (the update replaces it with the rest of the runtime). It looks huge (several GB apparent) but is hardlinked into `python-env/`, so its real cost is a few tens of MB — and once the wheelhouse is gone it is the only local source an offline `uv pip sync` repair can draw from. Do not add it to any sweep.

**ComfyUI bump ritual** (step 5 re-derives the first-party node package):
1. *Baseline first.* With the old install on `:8000`, render a fixed set of same-seed songs through the app graph (`buildGraph`) and keep the MP3s — the only way to learn whether the new version performs identically for the same seed.
2. *Acquire + pin.* Fetch the tag's **commit** archive (`/archive/<sha>.tar.gz`) into an empty scratch dir; confirm `comfyui_version.py`; `node scripts/tree-digest.mjs <tar.gz>` gives `treeSha256` + nominal `size`. Edit `components.json`: `manifestVersion`, the `comfyui` item (`version`, `commit`, `url`, `size`, `treeSha256`), and `python.exclude` = exactly the `comfyui-workflow-templates-media-*` names the new templates wheel declares. Gate: `node scripts/check-manifest.mjs --no-network`, `node --test scripts/tree-digest.test.mjs physical-release/lib/layout.test.mjs`.
3. *Re-lock.* `npm run lock:python` (no `--freeze`). Review the wheel diff, then `npm run check:manifest`, `node scripts/check-manifest.mjs --wheelhouse .lock-work\wheelhouse`, `npm run typecheck && npm test`.
4. *Rust/scripts.* Grep for every dropped package (`components.rs` headless probe) and every ComfyUI flag (`supervisor.rs`, `scripts\dev-comfy.ps1`); read the new `comfy/cli_args.py` for deprecations. `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
5. *Nodes.* Diff `comfy_extras/nodes_yue2.py`, `comfy/text_encoders/yue2.py`, `comfy_extras/nodes_preview_any.py` and `comfy_execution/progress.py` old→new: input names/defaults, the `seconds` output, progress `max` semantics, PreviewAny's `{text:[…]}` shape. Any default the graph relies on implicitly (e.g. `cfg_scale`, omitted ⇒ 1.0 with a plan) must still mean the same. Then re-derive `comfy-nodes/ComfyUI-Stillsong2` (its README has the steps): re-apply the `Stillsong:` blocks to a fresh copy of `_generate`, re-check `stillsong_encode` against `encode_token_weights` and the replay against `Llama2_.forward` / `init_kv_cache`, do the residual diff, update `PINNED_YUE2_SHA256` (`cargo test first_run_headless` holds it to the pinned ComfyUI), and confirm `comfy/cli_args.py` still has both custom-node flags and `server.py`'s `/upload/image` still takes `type=temp`.
6. *Provision.* `STILLSONG2_E2E_COMPONENTS=C:\ss<ver> STILLSONG2_E2E_SKIP_MODELS=1 cargo test first_run_headless -- --nocapture` (short path), junction `models\` and `comfy-data\models\`, write the current `manifestVersion` into `.install-complete`, start ComfyUI from it.
7. *Live gates* (one renderer on the GPU): boot log clean (the package's import line, no `IMPORT FAILED`) → `node scripts/nodes-smoke.mjs` → `npm run test:live` → same-seed MP3 audio vs step 1 → timing vs the old version → `STILLSONG2_COMPONENTS=C:\ss<ver> npm run tauri dev`: photo → song, a keep-melody remix, a lyric edit.
8. *Docs.* `rg` the old version/commit/package names; this file's measured facts.
9. Leave the working tree uncommitted for the human.

## Hard-won facts (measured; do not rediscover)

**GPU / process**
- Never run the LLM and a render concurrently (measured on Stillsong 1: ~6× slower with Gemma resident). The VRAM arbiter is mandatory.
- Fresh WS `clientId` per job, socket open before `/prompt` submit. ComfyUI keys sockets by clientId and pops the key when an old socket disconnects — reuse lets job N's teardown evict job N+1's socket and silently drop all progress. History polling every 10 s is the fallback; 3 transport errors on a dead ComfyUI fails the song.
- YuE2 speed, RTX 5080, int8 checkpoint, default (fp16) VAE, warm (measured 2026-11-10, ComfyUI v0.42.4): melody plan 5–14 s (~1.8–5 k chars of ABC); music tokens ~205/s (≈ 8 s of song per second); 32 KSampler steps 14–28 s for a 3.5–5 min song; decode ≈ 1.2 s. A 4–5 min song ≈ 50–85 s wall. Peak VRAM 12–16 GB on the 16 GB card (including ~2.5 GB other apps), highest on long songs; ComfyUI's dynamic VRAM absorbs it.
- Also measured 2026-11-10 and not chosen: the bf16 checkpoint (~145 tok/s, ~30% slower, 7.8 GB) and `--fp32-vae` (decode +12.5 s, peak 15.9 GB). After listening, the user found int8 + the default VAE sounds fine and chose it.
- The `comfyui-workflow-templates-media-*` wheels are excluded on purpose (`python.exclude`); keep the meta/core/json template packages (dropping the meta package triggers a multi-line ERROR banner). Do not ship the media.

**YuE2 contract** (`comfy_extras/nodes_yue2.py`, `comfy/text_encoders/yue2.py`)
- Graph = the official `audio_yue2_text2music.json` template unwrapped. One seed feeds `YuE2GenerateABC`, `YuE2GenerateMusic` and `KSampler`; KSampler 32 steps, cfg 1, `dpm_2`, `sgm_uniform`, negative = `ConditioningZeroOut`. `EmptyYuE2LatentAudio` must take `YuE2GenerateMusic` output 1 (`seconds`) or the model raises.
- Prompt = `"{instruction}\n[Tags]\n{style}\n[Lyrics]\n{lyrics}\n"`; there is no language field or instrumental flag. Stillsong 2 sends Stillsong 1's three-section caption as the style (the user's own YuE2 tests used it). Upstream's guide suggests a compact comma-separated line instead; it was rendered for comparison on 2026-11-10, and the user chose to keep Gemma's output unchanged for now — caption experiments come later. Instrumentals keep v1's tag-only lyrics (`instrumentalSkeleton`); they range widely in length (72–404 s for the same 9-tag skeleton across seeds/caps).
- `max_duration` is **fixed at 500 s** (`MAX_DURATION_SEC`) for every song. It sizes the music KV cache, so it changes the performance for the same seed (300 → 400 changed the audio) — never vary it between a song and its remixes. The music budget is `min(max_duration × 25, 24576 − prompt tokens)`; style + lyrics + plan all count. v1-length lyrics (44–58 lines) end on their own at 215–330 s; at a 300 s cap 2 of 8 truncated.
- `seconds` = music tokens actually written / 25; truncation is only a log line plus a conditioning flag. The harvest reads `seconds` through a `PreviewAny` (`seconds_out`) and flags `hitCeiling` when it fills the cap or when the `perform` node's final progress reaches its (possibly prompt-shrunk) budget. The end token is checked every 16 tokens, so a natural end can overshoot by ≤ 15.
- The melody plan (ABC) is a plain STRING: harvest reads it from `plan_out` (`PreviewAny`), the song stores it as `plan_abc`, a remix passes it back literally as `spec.abc` (no plan node in that graph). It holds `V: Vocal` / `V: Ins` voices, chord symbols and `% section` comments, **no lyrics**. An empty `abc` makes the node run with no plan (`off`, cfg 1.01).
- Progress: `YuE2GenerateABC` (`plan`) emits WS `progress` per token with `max` = `max_abc_tokens` (8192, a ceiling, not an estimate); `YuE2GenerateMusic` (`perform`) with `max` = its token budget (12500 for 500 s) — the bar stops wherever the song ends. Acoustic conditioning emits nothing; KSampler (`sample`) as usual. Node ids are stable strings mapped in `NODE_PHASES`; the store keys stages on the `Composing…`/`Rendering…` prefixes.
- **Determinism** (2026-11-10): same seed + same inputs + same `max_duration` ⇒ byte-identical MP3 audio frames, across a ComfyUI restart; the generated plan vs. the same plan passed literally ⇒ identical. Same plan + new seed, or same plan + an edited lyric line ⇒ the melody stays recognizable while voices/instruments shift. Core ComfyUI has no continuation and no token forcing; "Enhance quality" and "Let it finish" do not exist in Stillsong 2 (YuE2's 32 steps are upstream's converged default). Partial re-performance is the first-party package's job (next section).
- `SaveAudioAdvanced`: `format: "mp3"` + dotted sub-input `"format.quality": "V0"|"128k"|"320k"`. History output subfolder uses backslashes; `/view` accepts both.
- Seeds are TEXT end-to-end, app-generated < 2^53. `max_duration` grid is 0.04 s.
- Weights license: CC BY-NC 4.0 with the authors' individual-creator permission, in multimodal-art-projection/YuE `MODEL_LICENSE` (pinned at `cbb3b060`, 2026-09-16, in `physical-release/licenses.json`). **Takes and partial re-performance** (measured 2026-11-12/13, RTX 5080, ComfyUI v0.42.4; the user listened to the results)
- Why a reworded line changes the whole song: the lyrics sit in the prompt ahead of the music tokens, so with one line edited (same seed, same plan) the sampled tokens diverge within about 10 of thousands, and the acoustic stage then denoises every frame jointly. Measured: the keep-melody same-seed remix is 6.6–14 dB (log-mel) from the original everywhere; by ear, instruments and vocals shift throughout.
- The tokens are the performance: all tokens forced with only the prompt's lyrics edited is within 0.2 dB of the original.
- Forced tokens outside a window + the original latent held outside it (`noise_mask` 1 inside) ⇒ decoded audio outside the window is sample-identical, apart from about half a second before and after each seam (decoder reach). The song keeps its length. By ear: identical outside, smooth seams. Tokens spliced but the latent fully re-denoised drifts about 1 dB everywhere, so the hold is what makes it exact. KSampler leaves held frames one rounding step off (max 1.5e-8 measured); `Stillsong2RestoreLatent` copies them back so they are bit-equal and chained edits cannot drift.
- Core nodes cannot do any of it: no token input or output, and `SetLatentNoiseMask` reshapes to 4D while `reshape_mask` needs 3D for a 1D latent. A `[1,1,T]` mask on the latent dict works.
- The sampling head is a captured CUDA graph (`step` is baked in): forcing must read per-step device tensors by `step_index`, never branch in Python. A forced step still draws and discards a sample, which keeps the RNG stream aligned (forcing a prefix under an unchanged prompt reproduces the take exactly). The end token is forced at the take's last frame and blocked inside windows; `max_duration` stays 500.
- Word timing comes from the model: replay a take (one batched forward pass over prompt + tokens, `lm_head` in chunks of 256 positions) under the original and the edited sheet; per frame, log p(edited) − log p(original), smoothed over 13 frames. Changed words drop to about −2 at their onsets against a noise sigma of about 0.016; nothing else in the song crosses −0.25. A replay takes 0.3–0.7 s (1.0 s for a 12,500-frame take), against 24–36 s stepped one token at a time; batched and stepped values differ by about 0.04 per token, so compare batched with batched. A line that repeats (three identical choruses) drops only in the chorus whose text was edited.
- Windows: spans below min(−0.25, −6σ), joined when closer than 5 s, padded 12 frames (`editWindows.ts`). Bar-counting from the plan is not good enough: on "The Last Ember" it opened the window 1.7 s late and the old first line stayed in (the user heard it; the plan's total was 1.2% off).
- The same series on the re-sung take is the check. Dips sit on word onsets, so a held last word can leave its tail just past the window (−11 nats at 161.3–161.8 s after a 159.1–161.5 s window on "Iron Ghost"); widening to cover it and re-singing cleared it. The kept tokens right after a window are always less likely than in the original (−17 to −20 nats in the first half second, even on takes that sound perfect), so that is not a usable seam test.
- A re-sung window is a new performance of those lines: a wide one can come out louder or fuller (a 48 s window was 3–5 dB louder than the original verse; windows that hug the changed lines stayed within 1 dB). Keep windows tight.
- An edit costs about one render (the edit prompt still steps every token; 38–66 s for 3–5 minute songs) plus about two seconds of replays.
- The MP3 carries its whole prompt, so the edit graph never contains the original lyrics: the alignment and the check are separate prompts.
- ComfyUI serves an identical save node from its cache and reports file names from the earlier run, so each edit attempt saves under a fresh prefix (`<id8>_<nonce>`, still matched by the output sweep).
- Not released upstream (2026-11-12): the tokenizer that turns audio into YuE2's music tokens, so imported audio cannot be edited this way. Upstream's own docs: "Editing renders a new complete recording."
- Untried: plan mode `off`, windows that change length, "re-sing this part" for unchanged words (alignment needs a lyric difference), "change from here onward" (measured to work on the rig, not built).

**llama-server**
- Context is fixed at launch (`-c 16384`); no per-request knob. Vision goes in the OpenAI content array as `{type:"image_url", image_url:{url:"data:image/jpeg;base64,…"}}` *before* the text part.
- Constrained JSON is OpenAI's nested `response_format: {type:"json_schema", json_schema:{schema}}`. For that type llama-server reads only `json_schema.schema`: the flat `{type:"json_schema", schema}` the app sent until 2026-10-27 was silently replaced by "any object" (verified live on b11429: enum and `maxLength` ignored; nested and `{type:"json_object", schema}` enforce both), so no schema bound applied before then. String `maxLength` is grammar-enforced — keep bounds on every string field (an unbounded compose rambled for 191 s).
- Gemma 4 thinks by default (b11429 and b12110), so `LlmClient` sends `chat_template_kwargs: {enable_thinking: false}` on every request (since 2026-11-05). The 12B template then prefills an empty thought channel, so no `reasoning_content` is generated and the schema grammar still binds the JSON. Measured 2026-11-05 on b12110 (real Cowriter, 5 photos × 2, 120 s target, warm RTX 5080): photo → lyrics 70.9 s mean (34–177 s) with thinking vs 13.1 s (10–15 s) without; card 11.9 → 3.3 s, compose 59 → 9.8 s; 10/10 linter-clean first try. Thinking also made the silent lint-repair turn fragile: on both builds about 1 in 6 forced repairs thought until the 16K context was full (`finish_reason: "length"`, ~12k tokens, ~150 s) and returned no JSON; without thinking 6/6 repairs succeeded in ~10 s. Trade-off: without thinking the lyrics run longer — `estimateSeconds` ≈ 213 s vs ≈ 160–184 s for the 120 s target — and are slightly more repetitive (42% vs 46% unique words).
- `/health` returns 503 while loading (~10–20 s). Awaiting process exit is the VRAM-clear guarantee. llama-server binds its port before loading the model; the supervisor checks the listener belongs to its Job Object before handing the URL on.
- Ollama's `/v1` is not a substitute in dev: it silently ignores context length (4K default) and guide-sized prompts overflow it.
- Pinned build is b12110 = the `v0.9.0` semver tag (llama.cpp's versioned tags are plain commits on master; binaries exist only for the nightly `b` builds, so pin the `b` number). It is the first pin with two Gemma 4 vision fixes: the encoder MLP now uses `gelu` instead of `gelu_quick` even for mmproj files without a `use_gelu` key (#30882), and non-square photos are no longer letterboxed (#30922). Windows CUDA 13 assets switched from `cuda-13.3` to `cuda-13.4` at b10977 (2026-09-15); 13.4 binaries run on any CUDA 13 driver (580+) via minor-version compatibility, except Turing (compute 7.x), which gets PTX only and needs the 13.4 driver branch (615+) — `driverShortfall` in `duration.ts` shows the setup notice. `--no-webui` is now a deprecated alias of `--no-ui` (still accepted).
- Vision cost is small; the card is the cost. Measured 2026-10-15 (RTX 5080, Gemma 4 12B Q4_0): every photo encodes to 508 image tokens (server caps the model's 1120 budget to `n_ubatch` = 512), prompt processing ≈ 0.25–0.5 s, and the ~1,000-token analysis card ≈ 10–12 s at ~89 tok/s. Raise `-ub` only if more image detail is ever wanted; it will not speed anything up.

## Conventions

- SQL: `?` placeholders, TEXT UUID ids from `newId()`. The full spec is denormalized as `spec_json` on the `song` row; remix/re-run reads it back, so keep it in sync with the columns (the original table's `dit_file` column holds the checkpoint name; `tiled_decode` is unused). `take_path` and `edit_windows` are plain columns written once, at harvest (`SongRepo.setOutput`).
- Engine → UI is events only (`Engine.on`). Keep the `refreshSeq` out-of-order guard in the store.
- Classic JSX runtime (`import React`). `tsconfig.test.json` adds `@types/node`; the app tsconfig excludes `src/engine/__tests__`. Path aliases (`@engine`, `@adapters`, `@state`, `@ui`) live in `tsconfig.json`, `vite.config.ts`, and `vitest.config.ts` — update all three.
- Copy follows the design-kit voice: no *VRAM / inference / model / render / prompt / generate* in primary UI; the engine is "the studio"; the ABC plan is "the melody" / "melody plan"; sentence case except eyebrow labels and "Create My Song".
- **Privacy by construction — keep it that way.** Photos are read as base64 solely for the local LLM call; `buildGraph` has no photo input; production CSP allows no remote hosts; both servers bind 127.0.0.1; the native bridge accepts only plain `http://`/`ws://` to loopback, follows no redirects, uses no system proxy; `http_download` writes only library-relative paths, and `http_upload` reads only library-relative paths and posts only to loopback (a take, to the studio's temp folder). The node package reads takes from ComfyUI's temp and output folders only, by name, and writes safetensors (never pickle). Every python/uv/llama-server child gets `scrub_inherited_env` (llama-server reads `LLAMA_ARG_*` for any flag, including b11744+'s `--connect` WebRTC tunnel). The setup downloader is the one deliberate exception (manifest-pinned URLs on `allowedHosts`, https-only hops).
- Releases are built and signed locally. `npm run tauri build` is unsigned by default; signing is a local, uncommitted `bundle.windows.signCommand`. There is deliberately no release workflow. Exported MP3s carry an ID3 AI-disclosure comment ("AI-generated music (YuE2), created locally with Stillsong 2.").
