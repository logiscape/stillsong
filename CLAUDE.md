# CLAUDE.md

Stillsong: a Windows desktop app (Tauri v2 + React 18 + TS) that turns a photo into a song that tells its story. One button: drop a photo, pick a voice (instrumental / female / male), get a finished song in a full-screen "Listening Sanctuary". Everything runs locally: ComfyUI renders music with MiniMax Music 3; Gemma 4 12B writes the lyrics/caption (vision + compose). Project is GPL-3.0.

Architecture: a pure dependency-injected engine in `src/engine/` (no UI/Tauri imports; all I/O behind `src/engine/ports.ts`), Tauri adapters in `src/adapters/tauriPorts.ts`, a thin Rust shell in `src-tauri/src/`. Tests inject in-process fakes (`src/engine/__tests__/`).

## Hard-won facts (measured on this hardware, mostly in the prototype that preceded this repo — do not rediscover)

- **Never run the LLM and a render concurrently.** With Gemma resident (8.4 GB), a 20 s render took 153 s instead of 22–27 s (~6×, no OOM — ComfyUI offloads). The VRAM arbiter (`src/engine/orchestrator/vram.ts`) is mandatory.
- **Speed (RTX 5080, models warm)**: 20 s song ≈ 22–27 s wall-clock (encode ≈ 11–12 s @ ~42 frames/s, KSampler 30 steps ≈ 11 s, tiled decode ≈ 1 s). Gemma: compose ≈ 10 s, photo card + compose ≈ 18 s.
- **Fresh WS clientId per job, socket open before `/prompt` submit** (`Engine.trackToCompletion`). ComfyUI keys sockets by clientId and pops the key when an old socket disconnects — reuse lets job N's teardown evict job N+1's socket, silently dropping all progress. Early events are buffered; history polling every 10 s is the fallback.
- **Prompt contract** (`comfy/ldm/minimax_music/prompt.py`): caption is Markdown-stripped; lyrics split on `[tag]` lines, `[start]` prepended by the model. **Instrumental = tag-only lyrics** (`[intro]\n[instrumental]\n[outro]`), never empty lyrics — A/B verified: empty lyrics drift off-caption (genre priors take over). Use only `[intro]/[instrumental]/[solo]/[outro]` tags: empty `[verse]`/`[chorus]`/`[bridge]` sections prime the model to invent gibberish vocals (they mark sung sections in training); the linter rejects them for instrumentals. Instrumental length (fixed-seed A/B, 2026-08-28, encode-only, identical caption, seeds 424242/133742): composed length is LINEAR in wordless tag count at ~9 s/tag from 3 to 15 tags (3 → ~27 s, 9 → ~74 s, 12 → ~109 s, 15 → ~139 s seed-mean), then BREAKS DOWN (18 and 24 tags both came out shorter than 15) — so a single pass reliably reaches only ~2:20. Arrangement style (gesture vs developed), a prose length statement, and "duration is N" metadata all showed NO effect beyond the ±15–35 s seed noise; there is no duration field in the caption contract. `instrumentalSkeleton` (cowriter.ts) therefore budgets 1 tag per 9 s clamped to 15, is sent in the compose request, and force-overrides Gemma's returned lyrics (never ask a small LLM to count; each lint miss costs a ~10 s repair round-trip). The linter still errors on sung tags / too-few tags as a backstop. Earlier in-app single renders that suggested tag count was non-monotonic were seed noise.
- **Target vs cap**: `spec.targetSec` is the aim; `spec.durationSec` = `renderCap(target, lyrics)` = `max(target, estimateSeconds) × 2 + 40`, ≤ 300, is the `max_duration` sent to ComfyUI. The cap costs nothing (pre-allocates the AR encoder's KV cache only; 360 s left 141 MB free on 16 GB, hence 300); output length = what the composer actually writes. Encode final progress within 1 s (25 frames) of max ⇒ truncated mid-phrase ⇒ `song.hit_ceiling`.
- **Composition = the AR code matrix** (one row of 8 RVQ codes per 40 ms frame; c0 < 16384, depth < 1024 — u16-safe, ~100 KB per 4-min song; SSC1 format in `src/engine/comfy/codes.ts` = `codes_format.py`). Measured 2026-08-28 on this machine: (1) same seed + same inputs ⇒ bit-identical codes; (2) with `kv_capacity_frames` pinned, changing `max_duration` leaves the shared prefix bit-identical (and even unpinned showed no drift at 12/16 s — the old "numerics drift" note overstated it, keep the pin anyway); (3) **teacher-forcing the full matrix + a higher cap = a bit-exact continuation** — the free frames after the forced prefix exactly matched an unforced longer run (RNG stream alignment holds across the eager forced path); (4) with an edited lyric the forced prefix holds bit-exact but generation diverges at the first free frame — there is NO "re-locking", so everything to keep must be inside the forced prefix (hence `editPrefixFrames` cuts at the edited section, erring early).
- The overlay is **pinned**: `PINNED_AR_SHA256` in `stillsong_ar.py` must match `comfy/ldm/minimax_music/ar.py` or the node refuses to load. On a ComfyUI version bump: re-apply the marked `Stillsong:` blocks to the new ar.py, update the hash, re-run `node scripts/overlay-smoke.mjs`.
- **Progress events**: the AR encoder emits WS `progress` with `max = max_duration × 25` audio frames, `data.node = "encode"`; KSampler emits steps with `node = "sample"`. `ProgressTracker` keys its ETA windows by node. Final encode value < max ⇒ natural ending, stored as `actual_sec`.
- **`SaveAudioAdvanced`** API format: `format: "mp3"` + dotted DynamicCombo sub-input `"format.quality": "V0"|"128k"|"320k"`. History output subfolder uses backslashes; `/view` accepts both.
- Seeds are TEXT end-to-end; app-generated seeds < 2^53 so `Number(seed)` is exact. The same seed feeds encoder and KSampler. `max_duration` grid is 0.04 s (25 fps, 9000-frame hard limit).
- Tiled VAE decode is the hard default (300 s untiled decode on 16 GB is unmeasured).
- **Tauri v2**: plugin commands need `src-tauri/capabilities/default.json` permissions — without them `Database.load` never resolves ("Starting engine…"). Restart `tauri dev` after editing capabilities. Native file drops are intercepted by Tauri: use `getCurrentWebview().onDragDropEvent`, never HTML5 `onDrop`. On Windows, `convertFileSrc` yields `http://asset.localhost/…` — the CSP must allow it in `img-src`/`media-src`.
- **llama-server specifics**: context is fixed at launch (`-c 16384`) — never rely on a per-request context knob; the OpenAI content array carries vision as `{type:"image_url", image_url:{url:"data:image/jpeg;base64,…"}}` with the image part *before* the text; constrained JSON is `response_format: {type:"json_schema", schema}` (llama.cpp's shape — NOT OpenAI's nested `json_schema.name/schema`); string `maxLength` in the schema is grammar-enforced — keep bounds on every string field (an unbounded compose was observed rambling for 191 s and dropping the Arrangement heading; COMPOSE_SCHEMA caps caption at 3600 chars); `/health` returns 503 while the model loads (~10–20 s from NVMe). Stopping the process (and awaiting exit) is the VRAM-clear guarantee.
- **Never assume Ollama's /v1 endpoint substitutes for llama-server in dev** — its OpenAI compat ignores context-length settings (silent 4K default) and guide-sized prompts overflow it.

## Conventions

- SQL: `?` placeholders, TEXT UUID ids from `newId()`, full spec denormalized as `spec_json` on the `song` row (remix/re-run reads it back — keep it in sync).
- Engine emits events via `Engine.on`; UI state in `src/state/store.ts` (useSyncExternalStore; keep the `refreshSeq` out-of-order guard).
- Classic JSX runtime (`import React`). Tests have `tsconfig.test.json` (adds @types/node); app tsconfig excludes `__tests__/`. Path aliases live in `tsconfig.json`, `vite.config.ts`, `vitest.config.ts` — update all three.
- Official ComfyUI nodes plus our own vendored overlay (`comfy-overlay/ComfyUI-Stillsong`, pinned to the ComfyUI version) — **no third-party custom nodes**. Graph via `src/engine/comfy/graphBuilder.ts` + typed constructors in `nodes.ts`; node ids are stable strings mapped to phases in `NODE_PHASES` — renaming an id silently degrades progress text (the overlay encoder keeps the `encode` id).
- Privacy by construction: photos are read as base64 solely for the local LLM call; `buildGraph` has no photo input; production CSP allows no remote hosts; both servers bind 127.0.0.1; the native bridge (`http.rs`/`ws.rs`) accepts only plain `http://`/`ws://` to a loopback host (`loopback_url`), follows no redirects, uses no system proxy (`loopback_client`; reqwest's default would send 127.0.0.1 through a configured Windows/HTTP_PROXY proxy), and `http_download` writes only library-relative paths — the CSP alone never bounded IPC. Every python/uv child gets `scrub_inherited_env` (PYTHONPATH/PYTHONHOME/VIRTUAL_ENV/CONDA_PREFIX/UV_*/PIP_*) so a user's own Python setup cannot leak into ours. Keep it that way; the setup downloader (`downloads.rs`) is the one deliberate exception: it starts connections only at manifest-pinned URLs on `allowedHosts` and follows redirects only over https.
